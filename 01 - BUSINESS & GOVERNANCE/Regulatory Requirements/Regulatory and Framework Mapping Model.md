# Regulatory and Framework Mapping Model

## Executive Summary

Framework mapping helps organize cybersecurity work, but it does not prove compliance. Compliance requires defined scope, applicable requirements, evidence, and assessment.

## Important Distinction

| Phrase | Meaning |
|---|---|
| Aligned to | The control or practice is consistent with a framework concept |
| Mapped to | A relationship has been identified between a note/control and a framework requirement |
| Compliant with | The organization has evidence that applicable requirements are met within a defined scope |

Do not write "compliant with" unless formal compliance evidence exists.

## Common Frameworks

| Framework | Useful For | Vault Treatment |
|---|---|---|
| NIST Cybersecurity Framework | Organizing cybersecurity outcomes | Use for alignment where helpful; verify current version before publication |
| NIST Risk Management Framework | Structured risk and system control lifecycle | Use conceptually where appropriate |
| ISO/IEC 27001 | Information security management system requirements | Use for control governance concepts; do not claim certification |
| ISO/IEC 27005 | Information security risk management | Use for risk concepts where helpful |
| CIS Controls | Prioritized technical and operational safeguards | Use for control inspiration and mapping |
| MITRE ATT&CK | Adversary behavior and detection engineering | Map only when confident and relevant |
| COBIT | IT governance and management objectives | Use for governance context where useful |
| PCI DSS | Payment card data environments | Use only when payment card scope is established |
