# Risk Register Operating Guide

## Overview

A risk register is the operating record for known risks, ownership, treatment, status, evidence, and decisions. It should support action, not become an archive of unresolved concerns.

## Minimum Fields

| Field | Purpose |
|---|---|
| Risk ID | Stable identifier |
| Risk Scenario | Clear risk event statement |
| Asset / Process | What is affected |
| Risk Owner | Accountable decision-maker |
| Inherent Risk | Risk before controls, using approved method |
| Existing Controls | Current safeguards |
| Control Effectiveness | Evidence-based judgment |
| Residual Risk | Remaining risk after controls |
| Treatment | Mitigate, accept, transfer, avoid |
| Treatment Owner | Person driving action |
| Target Date | Expected completion date |
| Status | Open, treating, accepted, closed, overdue |
| Evidence | Links to assessment, finding, control test, approval |

## Operating Discipline

| Practice | Why It Matters |
|---|---|
| Use stable IDs | Prevents confusion across reporting cycles |
| Assign owners | Risk does not move without accountability |
| Track treatment dates | Allows overdue risk to be escalated |
| Link evidence | Prevents unsupported status claims |
| Review accepted risks | Acceptance should expire or be periodically reviewed |

## Common Failure Modes

| Failure Mode | Consequence |
|---|---|
| Risk register is only a spreadsheet | No workflow, evidence, or ownership |
| Too many low-value entries | Material risks are buried |
| No closure evidence | Risks appear resolved without proof |
| Permanent acceptance | Exceptions become hidden policy changes |
