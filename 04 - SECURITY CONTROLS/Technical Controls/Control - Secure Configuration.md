# Control - Secure Configuration

## Control Objective

Reduce risk from insecure defaults, misconfiguration, unnecessary services, and weak settings.

## Risk Addressed

Unauthorized access, privilege escalation, exposed services, weak logging, insecure protocols.

## Control Type

Preventive. Administrative and technical.

## Control Owner

VERIFY.

## Implementation Guidance

Define baselines by platform, monitor drift, review exceptions, integrate with build processes, and validate after changes.

## Evidence

Baseline standard, configuration scan results, build records, exception approvals, change records, remediation tickets.

## Control Testing

Compare systems to approved baseline and validate remediation of high-risk deviations.

## Failure Conditions

No baseline, unmanaged exceptions, drift, insecure defaults, unsupported protocols, missing logs.

## Metrics

Baseline compliance, high-risk deviations, exception count, remediation time.
