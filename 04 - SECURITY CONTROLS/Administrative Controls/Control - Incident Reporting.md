# Control - Incident Reporting

## Control Objective

Enable users, teams, and systems to report suspected security events quickly and reliably.

## Risk Addressed

Delayed detection, unreported incidents, unmanaged phishing, data leakage, fraud.

## Control Type

Detective and corrective. Administrative.

## Control Owner

VERIFY.

## Implementation Guidance

Define reporting channels, triage ownership, response SLAs, feedback loops, user education, and escalation criteria.

## Evidence

Reported phishing records, hotline/email/ticket records, triage notes, case records, user communications, incident tickets.

## Control Testing

Validate reporting channels work, reports are triaged, and actionable reports reach incident response.

## Failure Conditions

Unknown reporting channel, reports ignored, no triage owner, no feedback, no escalation.

## Metrics

Report volume, report-to-triage time, confirmed incident conversion, phishing report rate.
